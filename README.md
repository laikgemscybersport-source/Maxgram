# MAXgram — мессенджер в стиле Telegram и MAX

Веб-мессенджер реального времени: React + Vite на фронте, Node.js + Express + WebSocket на бэке.
Вход по номеру телефона с SMS-кодом, аудио/видеозвонки на WebRTC, полный набор вложений.
Работает в браузере и как **отдельное приложение для Windows** (Electron) — см. [Приложение для ПК](#приложение-для-пк).

## Возможности

### Аккаунт
- **Регистрация по номеру телефона**: `+7 (…) xxx-xx-xx`, 5-значный SMS-код, TTL 5 минут, 5 попыток ввода
- **Вход через Google** (OAuth 2.0 + PKCE, ключи вписаны в `secrets.js`; Яндекс, VK и OK убраны из доступа)
- Профиль: имя, `@username`, «о себе», загрузка фото (сжимается на клиенте)
- «Избранное» — личный чат с собой для заметок и файлов
- **Статусы присутствия**: «в сети», «не в сети», «был(а) только что / недавно / N мин назад / сегодня/вчера/на прошлой неделе в HH:MM», «невидимка» (статус скрыт), «не беспокоить»
- Выход и смена аккаунта, сессия живёт в токене (`localStorage`), перезагрузка страницы вход сохраняет

### Переписка
- Личные чаты, **групповые беседы**, **каналы** (публичные и закрытые), сообщения в реальном времени через WebSocket
- Статусы: отправлено ✓ → доставлено ✓✓ → прочитано ✓✓ (зелёные); удаление своих сообщений
- **Ответ на сообщение** (reply), **редактирование** своих сообщений, **пересылка** в другие чаты, **выделение** сообщений
- **Закрепление** сообщений (в личных чатах — любой, в группах/каналах — только администраторы)
- Индикатор «печатает…», счётчик непрочитанных, онлайн-статусы, разделители по дням, группировка
- Светлая и тёмная темы, адаптивная вёрстка (на телефоне список и переписка переключаются), панель эмодзи

### Каналы и группы
- **Создание канала или группы** через кнопку «+» → «Новый чат»
- **Публичные и частные** каналы/группы с @-адресом
- **Вкладки Частные/Публичные** в окне создания нового чата — поиск по каталогу discover
- **Подписка/вступление** в публичные каналы и группы в один клик
- В канале публиковать могут только администраторы, у подписчиков — только чтение
- Счётчик просмотров на публикациях канала (как в Telegram)
- Информация о группе/канале: описание, @-адрес, видимость, список участников/администраторов

### Вложения
| Тип | Как работает |
| --- | --- |
| Фото | выбор файлов, сжатие до 1600 px, лайтбокс по клику |
| Видео | `<video controls>`, лайтбокс |
| Файл | до 10 файлов за раз, до 64 МБ, скачивание в один клик |
| Аудиосообщение | запись с микрофона (MediaRecorder, opus/webm), волна + длительность |
| Видеокружок | круглое видео с камеры, предпросмотр, смена камеры, до 60 с |

| Контакт | «поделиться контактом» — визитка из справочника с переходом в чат |
| Мероприятие | название, время, место, описание + кнопки «Добавить в Google / Яндекс Календарь» |
| Звонок | в чате остаётся карточка со длительностью или пометкой «Пропущенный звонок» |

### Звонки
- Аудио- и видеозвонки **peer-to-peer на WebRTC**, сигнализация идёт по тому же WebSocket
- Соединение, гудки, входящий звонок с кнопками ответить/отклонить, таймер разговора
- Микрофон вкл/выкл, камера вкл/выкл, смена камеры, PIP собственного видео
- Занятая линия → автоматический отказ; офлайн-адресат → «Пользователь не в сети»

### Истории
- Публикация фото, видео и текстовых историй, видны 24 часа
- Прогресс-бар, автозакрытие, отметка о просмотре, удаление
- Панель историй над списком чатов

### Настройки чата (меню «три точки» над звонками)
- **Обои чата** — 8 готовых палитр + загрузка своего фото, тёмные/светлые темы
- **Запрет копирования** — скрывает экспорт, отключает копирование текста
- **Отключение уведомлений** (mute)
- **Экспорт истории чата** — HTML-архив, JSON с полной структурой, TXT-лента
- **Очистить историю** / **Удалить чат** — с подтверждением

### Реальные SMS вместо показа кода на экране

По умолчанию стоит демо-режим: код показывается на экране. Реальных способов доставлять коды три: **SMS Gateway for Android** (`smsgate` — телефон с SIM + бесплатное облако провайдера, телефон доступен из любой сети), **TextBee** (`textbee` — то же приложение на Android, но другое облако), **свой шлюз из телефона с SIM** (`http` — бесплатно и без сторонних сервисов, но телефон должен быть доступен серверу) или **коммерческий SMS-шлюз** (SMS.ru, SMS Aero, Twilio — ключи выдаёт только провайдер после регистрации, придумать их нельзя). Второй шаг одинаков во всех случаях:

```bat
cd messenger
copy secrets.example.js secrets.js
notepad secrets.js
```

В `secrets.js` выбирают `sms.provider` и вписывают ключи выбранного шлюза (`secrets.js` в `.gitignore`, ключи не попадут в Git):

| `SMS_PROVIDER` | Шлюз | Где взять ключи | Переменные |
| --- | --- | --- | --- |
| `demo` | не нужен | — | — (код показывается на экране) |
| `smsgate` | **[SMS Gateway for Android](https://sms-gateway.app)** | дашборд → Settings / API | `SMS_GATE_KEY` (+ `SMS_GATE_URL`, `SMS_GATE_DEVICE`) |
| `textbee` | **[TextBee](https://textbee.dev)** | [app.textbee.dev/dashboard](https://app.textbee.dev/dashboard) → API keys | `TEXTBEE_API_KEY` (+ `TEXTBEE_URL`, `TEXTBEE_DEVICE_ID`) |
| `http` | **свой — телефон с SIM** | приложение на Android, ключи не нужны | `SMS_HTTP_URL` и др. (см. ниже) |
| `smsru` | [SMS.ru](https://sms.ru) | кабинет → «Настройки API» | `SMSRU_API_ID`, `SMSRU_API_KEY`, `SMSRU_FROM` |
| `smsaero` | [SMS Aero](https://smsaero.ru) | кабинет → «Интеграция / API» | `SMSAERO_EMAIL`, `SMSAERO_API_KEY`, `SMSAERO_FROM` |
| `twilio` | [Twilio](https://twilio.com) | console.twilio.com | `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` или `TWILIO_SERVICE_SID` |

Те же значения можно задавать переменными окружения — они приоритетнее файла (так удобнее на Render/Railway).

#### Телефон с SIM через облако (`SMS_PROVIDER=smsgate`) — рекомендованный

Подходит, если сервер лежит в интернете (Render, VPS), а телефон — дома или в кармане. Приложение **SMS Gateway for Android** на телефоне с SIM само удерживает канал с облаком шлюза: сервер пишет в их API, облако ставит задачу в очередь, телефон забирает её при следующем опросе (около 10 секунд) и отправляет SMS своей SIM. Телефон не обязан иметь белый IP, порт или туннель. Расход — SMS вашего тарифа, абонплата сервиса не нужна.

1. На телефон ставится приложение SMS Gateway for Android, регистрируется в аккаунте и привязывается к нему (в приложении видно номер телефона).
2. В дашборде [app.sms-gateway.app](https://app.sms-gateway.app) → **Settings / API** создаётся ключ вида `sboxk_live_…` (показывается один раз — скопируйте сразу).
3. В `secrets.js`:

```js
sms: {
  provider: 'smsgate',
  smsgate: {
    base_url: 'https://app.sms-gateway.app/api/v1',  // облако из дашборда
    key: 'sboxk_live_…',                             // ключ из Settings / API
    username: '',   // альтернатива ключу для self-hosted сервера шлюза
    password: '',
    device_id: '',  // если телефонов несколько — id нужного
  },
  // ...
},
```

4. Проверка:

```bat
npm run doctor                          :: ключ принят? телефон на связи? (SMS НЕ отправляются)
npm run doctor -- --test +79991234567   :: отправить одно настоящее SMS
```

`doctor` без `--test` делает только `GET /devices`: он показывает, что ключ подходит и устройство в сети, — это безопасно и бесплатно. Для self-hosted сервера шлюза укажите `base_url: 'https://api.sms-gate.app/3rdparty/v1'` и вместо ключа впишите `username`/`password` — сервер сам получит короткоживущий JWT и будет переиспользовать его до истечения.

#### TextBee (`SMS_PROVIDER=textbee`) — то же приложение, другое облако

Если ключ `sboxk_live_…` не работает (отвергается сервером), возможно он из другого облака. TextBee (`textbee.dev`) использует то же приложение на Android, но **другое облако и другой API**. Ключ от sms-gateway.app здесь не работает, и наоборот.

1. Зарегистрируйтесь на [app.textbee.dev/dashboard](https://app.textbee.dev/dashboard) (или `sms.prominder.pl`).
2. Отсканируйте QR-код из панели, чтобы привязать телефон с SIM.
3. В дашборде создайте API-ключ вида `txb_…`.
4. В `secrets.js`:

```js
sms: {
  provider: 'textbee',
  textbee: {
    base_url: 'https://api.textbee.dev/api/v1',  // облако TextBee
    api_key: 'txb_…',                            // ключ из API keys
    device_id: '',  // id устройства из панели (или пусто — возьмётся первое)
  },
  // ...
},
```

5. Проверка:

```bat
npm run doctor                          :: ключ принят? телефон на связи? (SMS НЕ отправляются)
npm run doctor -- --test +79991234567   :: отправить одно настоящее SMS
```

`doctor` без `--test` делает только `GET /gateway/devices`: показывает, что ключ подходит, устройство включено и помечено основным, — это безопасно и бесплатно. Отправка идёт на `POST /gateway/devices/<id>/send-sms`, авторизация — заголовок `x-api-key` (не `Authorization: Bearer`), успешный ответ — HTTP 201.

Два отличия этого облака, о которых стоит знать:

- **Статуса отдельного SMS нет** — эндпоинтов `get-sent-sms`/`sent-sms` у TextBee не существует (404). Понять, что сообщение реально ушло, можно по счётчику `sentSMSCount` в `GET /gateway/devices`.
- **Входящие приходят в облако с задержкой** (минуты, иногда больше). Отправке кода это не мешает — пользователь читает SMS на экране телефона, — но автозаполнение кода из облака по `GET /gateway/devices/<id>/get-received-sms` мгновенным не будет.

Ключ даёт право отправлять SMS с вашего телефона и за ваш счёт. Не пересылайте его и не вставляйте в переписку, скриншоты или issues: если ключ где-то засветился — отзовите его в том же API keys и создайте новый, `secrets.js` в `.gitignore`, так что в репозиторий он не попадёт.

#### Свой шлюз на телефоне (`SMS_PROVIDER=http`) — без договора и денег провайдеру

Понадобится любой Android-телефон с SIM, который работает дома в той же Wi-Fi сети, что и сервер. Расход — SMS вашего тарифа, никаких регистраций и ключей.

1. На телефон ставится приложение-шлюз, поднимающее HTTP-сервер: **«SMS Gateway - The SMS Forwarder»** (в настройках включается «HTTP API» — там же виден адрес вида `http://192.168.1.50:8080`) или аналог. Телефон с этого момента — ваше SMS-оборудование.
2. В `secrets.js` указываются адрес и имена полей, которые понимает это приложение:

```js
sms: {
  provider: 'http',
  http: {
    url: 'http://192.168.1.50:8080/send',  // адрес из приложения
    method: 'POST',        // POST или GET
    format: 'form',        // form (x-www-form-urlencoded) или json
    phone_field: 'to',     // как у шлюза называется поле номера
    text_field: 'message', // …и поле текста
    token: '',             // если приложение требует пароль → Authorization: Bearer …
    expect: '',            // если шлюз всегда отвечает 200: подстрока успеха, напр. 'OK'
    extra: '',             // прочие поля: {"password":"1234","client":"maxgram"}
  },
}
```

3. Проверка:

```bat
npm run doctor -- --ping            :: достижим ли телефон (без отправки SMS)
npm run doctor -- --show            :: показать точный запрос, который уйдёт на шлюз
npm run doctor -- --test +79991234567   :: отправить одно настоящее SMS
```

`--show` — главный инструмент подбора: он печатает `POST http://…`, заголовки и тело запроса ровно в том виде, в каком их увидит шлюз. Сравните имена полей с документацией или подсказками приложения и поправьте `phone_field` / `text_field` / `format` / `expect` в `secrets.js`. Ни один из шагов не отправляет SMS, кроме `--test`.

Шаблон запроса настраивается полями, поэтому подходит любое приложение-шлюз: сервер подставляет номер и текст в указанные имена полей, выбирает form/json/GET и при необходимости добавляет Bearer-токен. Ошибки шлюза (недоступен, отверг номер, нет нужной подстроки в ответе) приходят пользователю как `502` с текстом причины, а не молча.

Для телефона, стоящего вне домашней сети, тот же `http`-шлюз работает через туннель (Tailscale — самый простой способ: адрес вида `http://100.x.y.z:8080`).

Проверить, что реально видит сервер:

```bat
npm run doctor              :: какие ключи заданы, готов ли шлюз, баланс на счёте
npm run doctor -- --test +79991234567   :: отправить одно настоящее SMS
```

Пока `SMS_PROVIDER` задан, но ключей нет, сервер отвечает `503` и называет недостающие переменные — демо-код при этом не утекает. На публичном сайте это важно: без лимитов бот обнуляет баланс шлюза за вечер, поэтому выдача кодов ограничена (`SMS_LIMIT_PHONE` — 5 на номер в час, `SMS_LIMIT_IP` — 20 с адреса в час; в демо-режиме лимиты отключены). Баланс шлюза виден в логах и в `/api/health` (`sms_ready`).

### Вход через Google

OAuth-флоу полностью написан и настроен: state, callback, обмен кода на сервере (`client_secret` в браузер не попадает). Из доступа убраны Яндекс, VK и OK — на экране входа одна кнопка, Google.

| Провайдер | Зарегистрировать приложение | Что вписать в `secrets.js` |
| --- | --- | --- |
| Google | [console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials) | `oauth.google.client_id`, `client_secret` |

Ключи хранятся только в `secrets.js` и в `%APPDATA%\maxgram\secrets.js` — оба пути в `.gitignore`, поэтому в репозиторий, в `maxgram-web.zip` и внутрь `.exe` они не попадают.

**PKCE обязателен.** Если клиент создан как «Desktop app» (в JSON-файле секция `installed`), Google при обмене кода требует `code_verifier` — без него отвечает `invalid_grant`. Сервер это учитывает: генерирует верификатор, кладёт в `oauthStates` рядом с redirect URI и передаёт при обмене (`code_challenge` + `code_challenge_method=S256` в URL авторизации).

Redirect URI:

```
http://localhost                                   для клиента типа «Desktop app»
https://<ваш-домен>/auth/google/callback           для «Веб-приложения»
```

Для desktop-клиента Google принимает `http://localhost` с любым портом и путём, поэтому вход работает локально, на туннеле и в Electron без правок — адрес редиректа сервер строит из заголовков запроса. Для боевого HTTPS-домена заведите отдельный клиент типа «Веб-приложение» с точным URI и зафиксируйте адрес в `PUBLIC_URL` (в `secrets.js` — `public_url`).

Вернуть остальных провайдеров можно, добавив их объекты в `OAUTH` (`server.js`) и в `config.js`: код обмена для Яндекса, VK и OK сохранён в истории git.

## Приложение для ПК

Готовые сборки лежат в `messenger\desktop\`:

| Файл | Что это |
| --- | --- |
| `MAXgram-Setup-1.0.0.exe` | Установщик: ярлыки на рабочем столе и в «Пуске», обычная установка с выбором папки |
| `MAXgram-1.0.0-x64.exe` | Portable-версия — запускается двойным щелчком, ничего не устанавливает |

Внутри — то же приложение, что и в браузере: сервер поднимается внутри окна на свободном порту, поэтому второй браузер или веб-сервер на `:3000` не мешают. Микрофон и камера для звонков и видеокружков разрешаются автоматически.

Переписка **сохраняется** между запусками в папке профиля Windows:

```
%APPDATA%\maxgram\maxgram-data.json    переписка, профили, каналы, истории
%APPDATA%\maxgram\uploads\             загруженные файлы
%APPDATA%\maxgram\secrets.js           ключи SMS-шлюза и OAuth (создаётся сам при первом запуске)
```

Ключи во встроенном сервере читаются из `%APPDATA%\maxgram\secrets.js` — файл создаётся автоматически с готовым шаблоном, открываете его в блокноте, вписываете `provider` и адрес шлюза, перезапускаете приложение. Так ключи не оказываются внутри собранного `.exe` и не теряются при обновлении программы.

Для веб-версии (`npm start`) сохранение на диск по-прежнему выключено — данные живут в памяти, как у хостинга без диска. Включается переменной `DATA_FILE` (её и передаёт Electron); интервал записи — `PERSIST_MS`, по умолчанию 4000 мс.

### Собрать заново

```bat

```

Скрипт сначала собирает фронт (`client\dist`), затем `electron-builder` кладёт в `desktop\` установщик и portable-файл. Иконка генерируется процедурно — `npm run icon` (`tools\gen-icon.js`), внешние изображения не нужны.

### Если окно не появляется

Приложение само проверяет переменную `ELECTRON_RUN_AS_NODE` и перезапускается без неё. Если всё же молча закрывается — последняя ошибка пишется в `%TEMP%\maxgram-desktop.log`. Ещё одна частая причина: сборка прервана, потому что запущенное приложение держит свои DLL — закройте MAXgram и соберите снова (`tools\rebuild-desktop.cmd` делает это сам).

## Публичный сайт вместо localhost

Сервер уже умеет работать за прокси и на хостинге: порт берётся из `process.env.PORT`, адрес для OAuth-редиректов — из `PUBLIC_URL`, статика отдаётся из `client/dist`, SPA-роуты и `/ws` обрабатываются одним процессом. Ничего менять в коде не нужно — только задать переменные окружения.

### Ошибка «Publish directory … does not exist!»

Так Render ругается на заполненное поле **Publish directory**: он ищет папку с таким именем в репозитории и не находит. Домен (`Maxgram.ru` и т. п.) в это поле вносить не нужно — адрес сайта Render выдаёт сам.

Исправить в **Dashboard → сервис → Build & Deploy**:

1. **Publish directory** — оставить пустым. Это Node-приложение, а не статический сайт: статику раздаёт `server.js` из `client/dist`.
2. **Build command** — `npm install --omit=dev && cd client && npm install && npm run build && cd ..`
3. **Start command** — `node server.js`
4. Если `messenger` лежит внутри репозитория, а не в его корне: **Build → Root directory** = `messenger`. Если вы заложили содержимое `messenger` в корень — это поле оставляют пустым, а `rootDir` в `render.yaml` удаляют.

### 3. Свой VPS (Ubuntu + Nginx)

```nginx
server {
  listen 443 ssl http2;
  server_name ваш-домен.ru;
  ssl_certificate     /etc/letsencrypt/live/ваш-домен.ru/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/ваш-домен.ru/privkey.pem;

  client_max_body_size 80m;          # загрузка файлов до 64 МБ

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade    $http_upgrade;   # WebSocket
    proxy_set_header Connection "upgrade";
    proxy_set_header Host       $host;
    proxy_set_header X-Real-IP  $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
  }
}
```

Сертификат: `sudo certbot --nginx -d ваш-домен.ru`.

### Что учесть в продакшене

| Вопрос | Решение |
| --- | --- |
| **OAuth** | Кнопка входа через Google уже настроена: ключи лежат в `secrets.js` (в `.gitignore`, в сборку не попадают), PKCE включён на сервере. Для своего клиента впишите `client_id`/`client_secret` или задайте `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`; для боевого HTTPS-домена разрешите redirect `https://<домен>/auth/google/callback`. Адрес сервера берётся из заголовков запроса, но за CDN/балансировщиком задайте `PUBLIC_URL`. Проверка: `npm run doctor`. |
| **SMS** | `SMS_PROVIDER=smsgate` + `SMS_GATE_KEY` (телефон с SIM через облако sms-gateway.app), либо `smsru` / `smsaero` / `twilio` + ключи шлюза в `secrets.js`. В демо-режиме код показывается на экране и лимиты выдачи отключены — на публичном сайте это небезопасно, переключитесь на реальный провайдер. Держите на счету баланс: он выводится в лог при каждой отправке. |
| **Хранилище** | Данные живут в памяти процесса: перезапуск очищает переписку, а на нескольких инстансах они не разделяются. `DATA_FILE` включает запись на диск (подходит для одного инстанса с постоянным диском), но для серьёзного использования замените объектные хранилища в начале `server.js` на SQLite/PostgreSQL и добавьте Redis-adapter для `sockets` (или держите один инстанс). |
| **TURN** | WebRTC работает через STUN, но за симметричным NAT и в некоторых мобильных сетях звонок не соединится без TURN. Поднимите `coturn` и допишите его в `ICE_SERVERS` (`client/src/webrtc.js`). |
| **Загрузка файлов** | `uploads/` на ephemeral-filesystem хостинга очищается — подключите том-накопитель или S3 (место расширения — `storage` в `server.js`). |
| **Безопасность** | HTTPS обязателен: токены лежат в `localStorage`, а WebRTC-микрофон/камера браузеры дают только на `https://` (кроме `localhost`). |

## Протокол

### Авторизация

| Метод | Путь | Ответ |
| --- | --- | --- |
| POST | `/api/auth/send-code` `{phone}` | `{ok, phone, sent, demo, demo_code?, ttl_sec}`; `demo_code` — только в демо-режиме. Ошибки: `400` номер, `429` лимит номера/IP, `502` шлюз отверг, `503` ключи шлюза не заданы |
| POST | `/api/auth/verify` `{phone, code}` | `{token, user}` **или** `{needs_profile, phone}` |
| POST | `/api/auth/register` `{phone, name, username?, bio?}` | `{token, user}` |
| GET/PUT | `/api/me` | профиль / обновлённый профиль |
| POST | `/api/me/avatar` (multipart `photo`) | `{user}` |
| POST | `/api/auth/logout` | `{ok}` — токен инвалидируется |
| GET | `/api/auth/providers` | `{providers:{google:{label,configured}…}, sms_provider, sms_ready, sms_name, sms_missing[]}` |
| GET | `/api/auth/:provider/start` | `{url}` — ссылка авторизации (501, если не настроен) |
| GET | `/auth/:provider/callback` | закрытие popup, код сохраняется в `localStorage` |

Все защищённые запросы требуют `Authorization: Bearer <token>`. WebSocket — `?token=<token>`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/users` | список профилей (с статусом присутствия) |
| GET | `/api/users/:id/chats` | чаты с превью, закрепом, настройками и непрочитанными |
| GET | `/api/chats/:key/messages` | история (отмечает прочтение, считает просмотры в каналах) |
| POST | `/api/chats/:key/read` | отметить прочитанным |
| POST | `/api/messages` | отправить сообщение (`reply_to` — ответ, `forwarded_from` — пересылка) |
| PUT | `/api/messages/:id` | редактировать своё сообщение |
| DELETE | `/api/messages/:id` | удалить своё сообщение (админ — чужое в своей группе/канале) |
| POST | `/api/messages/:id/pin` | закрепить / открепить (`remove: true`) |
| POST | `/api/messages/forward` | `{message_ids, chat_keys}` — переслать в несколько чатов |

| POST | `/api/chats/:key/wallpaper` | загрузить своё фото обоев (multipart `photo`) |
| GET | `/api/chats/:key/export?format=html\|json\|txt` | скачать архив переписки |
| POST | `/api/chats/:key/clear` | очистить историю |
| DELETE | `/api/chats/:key` | удалить чат (для групп/каналов = выход) |
| POST/PUT | `/api/groups` | создать группу (`is_public`, `handle`) |
| POST | `/api/groups/:id/join` | вступить в публичную группу |
| POST/PUT | `/api/channels` | создать канал (`is_public`, `handle`) |
| POST | `/api/channels/:id/join`, `/leave` | подписаться / отписаться |
| POST | `/api/channels/:id/avatar` | аватар канала (multipart `photo`) |
| GET | `/api/discover?q=` | каталог публичных каналов, групп и людей |
| GET | `/api/lookup-phone?phone=` | найти регистрацию ровно по номеру (уважает `privacy=invisible`) |
| GET | `/api/lookup-username?username=` | найти регистрацию по `@username`: точное совпадение — один профиль, частичное — список похожих |
| GET/POST | `/api/stories` | список историй / опубликовать историю |
| POST | `/api/stories/:id/view` | засчитать просмотр |
| DELETE | `/api/stories/:id` | удалить свою историю |
| POST | `/api/upload` (multipart `files`, до 10) | `{files:[{url,name,mime,size}]}` |

Ключ чата: `p:u1,u2` — личный (id сортируются), `g:g1` — групповой, `c:c1` — канал, `s:u1` — Избранное.

Сообщение: `{chat_key, kind, content, media?, location?, contact?, event?}`, где
`kind ∈ text, photo, video, file, audio, voice, circle, location, contact, event, call`.
Для `text` обязателен `content`, для `call` — описание, для остальных — хотя бы один из `media/location/contact/event`. Доступ к чату проверяет `canAccess`.

### WebSocket `/ws?token=`

Сервер → клиент: `users`, `message`, `receipt`, `read_all`, `delete`, `typing`, `call`.
Клиент → сервер: `typing`, `read` (с `chat_key`) и `call`:

```json
{ "type": "call", "action": "offer|answer|ice|ringing|reject|ended",
  "call_id": "c…", "to": "u2", "chat_key": "p:u1,u2",
  "video": true, "sdp": {…}, "candidate": {…}, "reason": "busy" }
```

Если адресат офлайн, звонящему приходит `action: "unreachable"`.

## Данные и ограничения

По умолчанию хранилище — оперативная память сервера, тестовые диалоги засеиваются при старте; загруженные файлы лежат в `uploads/`. Если задать `DATA_FILE`, состояние дополнительно пишется в JSON и восстанавливается на старте (на этом работает приложение для ПК, см. [Приложение для ПК](#приложение-для-пк)). Для серьёзного продакшена замените объектные хранилища в начале `server.js` на базу (SQLite/PostgreSQL): интерфейс доступа сосредоточен в `chatSummary`, `canAccess`, `recipientsOf` и обработчиках `server.js`.

Звонки работают напрямую (STUN Google/Twilio). В симметричном NAT или за корпоративным файрволом нужен TURN-сервер — добавьте его в `ICE_SERVERS` в `client/src/webrtc.js`.
